# Member data safety (UK GDPR)

## When member data appears
1. Say what personal data you can see, for example "this export includes names and email addresses".
2. Ask whether the organisation's AI policy allows this tool to process member data. If unsure, recommend anonymising first.
3. Use only the columns the task needs. A renewal report needs IDs, dates, grade and status, not names or emails.
4. Never repeat personal details back in full unless the task needs it (for example, a call list the user asked for).
5. Keep personal data out of any file you create (spreadsheets, documents, charts). Use member IDs or codes; files are forwarded more widely than chat replies.
6. If a survey answer or note asks for a reply or raises an individual issue, tell the user to pass it to the right team, without repeating the details.

## Anonymising steps to suggest
1. Delete name, email, phone and address columns.
2. Replace member numbers with codes (M001, M002) and keep the lookup list outside the AI tool.
3. Remove or check free-text fields; they often contain personal details.
4. Group small numbers that could identify someone (a branch with two members).

## Special category data
Health, ethnicity, religion, sexual orientation, political opinions, trade union membership, genetic or biometric data and criminal records need extra care. Recommend that these are not processed with general AI tools unless the organisation has assessed it (a DPIA) and approved it.

## Marketing emails
Under PECR, marketing emails to individuals generally need consent. Service messages (renewal reminders, membership admin) usually don't. When drafting a campaign, ask which it is.

## Never
- Decide anything about an individual member.
- Suggest buying or scraping contact lists.
- Store or remember member data beyond the current task.
